# Как запускать LangTeacher

Виртуальное окружение: `/home/user/data/python-envs/langteacher` (уже настроено).

В качестве LLM-репетитора используется **твоя подписка Claude Code**, а не
отдельный платный API-ключ и не локальная GGUF-модель. Код LangTeacher про
это ничего не знает — он думает, что говорит с обычным `llama-server`.

Реализовано это через `~/langteacher/claude-llama-proxy` — маленький
Rust-сервер, который слушает `127.0.0.1:8080` (адрес по умолчанию для
LangTeacher) и изнутри держит один постоянный процесс `claude -p
--output-format stream-json`, переводя между HTTP-протоколом llama.cpp и
этим процессом. Прокси сам ходит наружу через `127.0.0.1:8118` (как и
`~/claude.sh`) — LangTeacher об этом прокси не знает и не должен.

Лог всех реплик пишется в `~/langteacher/claude-llama-proxy/logs/conversation.log`.

Голос репетитора — **Piper** (CPU, без клонирования голоса). От OmniVoice
отказались — он клонирует голос через GPU, но оказался слишком тяжёлым для
видеокарты. Голоса Piper (`.onnx` + `.onnx.json`) лежат в
`~/langteacher/piper_voices/`, `TTS_ENGINE=piper` — переменная окружения,
задающая бэкенд синтеза речи в `tts_engine.py`.

## 1. Запустить прокси

В одном терминале, один раз на всё время сессий:

```bash
cd ~/langteacher/claude-llama-proxy
./run.sh
```

Держи терминал открытым. Первая реплика сессии фиксирует системный промпт
(персону репетитора) на всё время жизни процесса — если он поменяется
(например, поменял язык/уровень и перезапустил `main.py`), нужно перезапустить
и `run.sh`, иначе прокси продолжит отвечать старой персоной.

## 2. Запустить репетитора

В другом терминале:

```bash
cd ~/langteacher
./1-run-tutor.sh
```

При первом запуске спросит язык, уровень, родной язык, способ ввода/вывода —
сохранится в `config.<hostname>.ini`. Push-to-talk — удерживать правый Shift.

## 3. (Опционально) Загрузить свои материалы в RAG

```bash
./2-ingest-rag.sh path/to/book.pdf --book "Book Name" --language de --level A2
```

Это отдельная функция (поиск по своим PDF-материалам), не связана с выбором
LLM-бэкенда. Требует отдельного embedding-сервера (`EMBED_HOST`/`EMBED_PORT`,
по умолчанию `127.0.0.1:8081`) через `llama-server` с моделью типа `bge-m3` —
если не нужен, просто не запускай этот скрипт (`RAG_ENABLED=false` тоже
отключает RAG в `main.py`).
